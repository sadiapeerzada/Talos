Before live use, the operator must supply a reviewed OS deployment that denies networking (including native sockets), isolates filesystem access to the exact required source/runtime/model/approval inputs and owned temporary outputs, excludes target-state/oracle/reviewer/other-run files, supervises every descendant including separate/escaped sessions, terminates/reaps on deadline/coordinator death, and independently observes finality. The deployment must remain compatible with Metal and the pinned loader; compatibility cannot be inferred from package imports. This PR intentionally supplies no untested permissive sandbox profile masquerading as verified containment.

For all new native operation, signed containment evidence binds the actual supervisor PID and three regular-file `os_control_reports`: `network_denial`, `filesystem_isolation`, `process_tree_finality`, each with path and SHA-256. Contents must include actual mechanism/configuration/version/source identities, test procedure and raw observations under the actual supervisor/user, scope and date, failures/limits, and genuine independent reviewer/custodian provenance. The coordinator checks its actual parent; the request child rechecks signed custody and actual coordinator identity, without claiming to inspect the external supervisor. The gate rehashes those files, while seven role signatures bind the containing evidence and exact plan. A self-declared Boolean or report hash is not proof of enforcement; responsible humans must inspect the actual deployment. No report, reviewer decision or reviewed PID is fabricated here.

A separate OS closure review is necessary before first real use. All existing original attack-delivery rules remain; stricter prospective native evidence requirements do not retroactively rewrite B1 or historical result records. Changed source fingerprints require fresh signatures. No stronger containment claim is made for historical or HTTP paths.
